## CDN 缓存头排查（JS 资源 no-cache）
- 用户反馈 admin-bindings.js 经 CDN 代理时带 Cache-Control: no-cache。
- 排查方法：教用户用 `curl --resolve <域名>:443:<源站IP>` 绕过 DNS/CDN 直连源站，确认源站真实响应头。
- 根因定位：curl -sIv --resolve 直连源站显示 `server: openresty`、HTTP 200、有 last-modified/etag，但**完全没有 Cache-Control 头** → 源站 nginx 未给 /plugins/ 静态资源配置缓存策略。
- 推断链条：此前 404 时资源缺失 → nginx 转给 index.php(Laravel) → Symfony ResponseHeaderBag 的 "conservative by default" 补 no-cache,private → Cloudflare/浏览器记住了该响应；现在文件已 200 但缓存行为残留。
- 代码层证据：vendor/symfony/http-foundation/ResponseHeaderBag.php:271 `return 'no-cache, private';`（无显式缓存头时的默认值）。BS 源码唯一显式 Cache-Control 在 AuthController.php:333（no-store，认证响应，与静态资源无关）。
- 建议方案：A) 源站 OpenResty 加 `location ~* ^/plugins/.+\.(js|css|...)$ { add_header Cache-Control "public, max-age=2592000"; try_files $uri =404; }`（勿同时用 expires + add_header 以免重复头）；B) Cloudflare Cache Rule 匹配 URI 含 /plugins/ 设 Cache everything + Edge/Browser TTL。插件已有 ?v=1.3.0 版本号做缓存破坏，可放心设长缓存。
- 验证：走 CDN（不带 --resolve）请求，应见 cache-control: public,max-age + cf-cache-status: HIT。
- **已解决**：用户在源站 OpenResty 加了 location 块后，直连验证显示 `cache-control: public, max-age=2592000` ✓，且 `strict-transport-security: max-age=31536000` 也已恢复 ✓（之前因 nginx add_header 继承规则丢失，加上 `always` 参数后修复）。
- 副作用教训：Nginx 的 add_header 在子层级出现时会停止继承父级所有 add_header，需显式重写或加 always。

## 用户环境信息
